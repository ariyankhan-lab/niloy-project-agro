# Development and deployment setup
Use the existing isolated /workspace/niloy-project-agro checkout in this cloud environment. Do not create worktrees unless the user requests them. Run npm ci from the checkout, then npm run check. npm run dev starts Vite; verify the actual foundation HTML with a local request and use browser tests for language and layout behavior. Do not publish loopback preview links during onboarding.

## Local Supabase
Docker must be available. npx supabase start initializes a local database and applies migrations; the minimal command in README.md excludes optional services. Never echo status credentials into CI logs. The CLI may use its supported ghcr.io fallback when its default public.ecr.aws registry is blocked. Do not disable TLS, signatures or checksums, or bypass network policy. Local runtime keys are generated by Supabase, never committed.

A hosted Supabase project is optional for foundation shell development. Configure only public URL/key in .env.local when supplied. Do not automatically link or migrate a remote database. Require explicit authorization and verify backups and target project before production migration.

## Frontend hosting (planned, not deployed)
Build: npm ci && npm run build. Output: dist/. Set the public build-time VITE_ variables in the hosting environment. For a static host, rewrite non-file paths to /index.html for BrowserRouter. Use HTTPS, review CSP and auth redirect allowlists for the actual domain, and keep source maps/secrets policy explicit. Vercel/Docker deployment is a future reviewed step; no deployment has been performed.

## GitHub
The CI workflow runs npm ci, lint, typecheck, Vitest and build, installs Chromium with trusted TLS, then runs Playwright. No production credentials are needed. For this managed machine an installed system browser can be selected with PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH. Review generated artifacts before adding files. Commits and pushes are not performed automatically.

## Current preview and authentication scope
The frontend dev server can show the workspace/login preview without backend credentials. For real sign-in, configure VITE_SUPABASE_URL and VITE_SUPABASE_PUBLISHABLE_KEY in ignored local or secure environment settings and apply both migrations to an explicitly authorized target. Provision accounts in trusted Supabase administration; no production signup or fake account is created by the preview. Do not expose recovery or invitation token fragments in screenshots.

The managed instance now runs the smaller, locally verified stack documented in [LOCAL_AUTH.md](LOCAL_AUTH.md). Its gateway is a development adapter, not a production deployment.
